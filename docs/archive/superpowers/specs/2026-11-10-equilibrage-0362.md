# Équilibrage 0.36.2 — décisions confirmées, livraison privée

Le parent a validé une à une les sept décisions : bonus réservé aux carapaces ;
baisse des trois prix ; rappel discret ; T-rex 340 ; bébé dragon 210 ; tank 440 ;
rappel après dix secondes avec 500 pièces utilisables. Le GO initial des cinq
propositions de caprices reste applicable après vérification. Les valeurs ont
été explorées sur 1 356 nouvelles parties (preuves ignorées
`artifacts/balance-next-20261110/`), distinctes des 1 080 de la revue précédente.
Ce document consigne les choix déjà approuvés ; aucune nouvelle validation des
mêmes valeurs n’est demandée. Choix techniques ci-dessous : coordinateur.

## Comportement approuvé

- Nouveaux départs : T-rex 340, bébé dragon 210, tank 440 pièces. Aucune autre
  statistique ou condition de déblocage ne change. Tank toujours vague 9 classique.
- `carrefour-grand` : count 1,5 → 1,2 ; `sonnette-grand` : hp 2 → 1,75.
- `refuge-createur-moyen` : shellEvery 2, shellHp 5, shellArmor 0,7,
  shellSpeed 0,6, **shellBite 1,5**, bite global reste 1. Seuls les ennemis
  marqués shell frappent plus fort ; représailles exactes 2/3 et dégâts d’entrée
  au cristal restent inchangés.
- `trois-ponts-createur-moyen` et `course-createur-moyen` : shellEvery 2,
  shellHp 5, shellArmor 0,6 ; shellSpeed reste 0,5, bite reste 1.
- Rappel exact « Tu as des pièces, recrute ! », traduit autour des noms français.
  Il faut 500 pièces dépensables (gold − reserve) pendant dix secondes réelles
  de combat actif sans recrutement. Toute baisse sous le seuil ou tout achat
  remet ce délai à zéro. Pause, accueil, onglet masqué, dialogue/rotation ou pose
  ne font pas progresser le délai. Au plus une apparition par départ/tentative ;
  conserver un marqueur UI borné par code de départ pour les reprises et réessais
  afin d’éviter de répéter le conseil. Stockage refusé : repli mémoire, pas de crash.
  Le rappel ne concurrence pas un danger/événement prioritaire, ne coupe pas le
  jeu et occupe la ligne basse existante, jamais les voies. Affichage lisible
  quatre secondes actives maximum, annulé après un recrutement ; pas de nouveau
  panneau. Une place légale pour au moins un allié recrutable doit exister.

## Compatibilité : une révision explicite

Éditer les valeurs du catalogue historique modifierait les anciens codes/camps ;
ce choix est exclu. Des snapshots arbitraires de toutes les règles seraient plus
lourds. Choix retenu : deux révisions immuables, 1 historique et 2 ci-dessus.

- `src/balanceRevision.ts` : type `BalanceRevision = 1 | 2`, constante
  `CURRENT_BALANCE_REVISION = 2`, `balanceRecruitPrice(kind, revision=1)`.
  `src/data.ts` et les 36 définitions historiques conservent leurs valeurs.
- `MissionRun.balance?: 2`, absent = historique. `readMissionRun` conserve 2,
  rejette les révisions inconnues. `createMissionRun` garde ses trois paramètres
  et accepte un quatrième `balance?: 2` ; défaut historique pour les anciennes API.
- `Game.balanceRevision` readonly ; quatrième argument constructeur optionnel
  pour le classique. Défaut mission.balance ou 1 ; incohérences/versions inconnues
  rejetées. `Game.recruitCost` utilise la révision et conserve les bons gratuits.
- `CapriceRules.shellBite?: number` facultatif, absent = 1, borné 1..3. N’ajouter
  aucun champ aux objets de règles historiques. Résolution révisée stable/cache
  dans `capriceRules(run)` et `capriceDefinitionForRun(run)` pour rendu/conseils.
  Aucun objet alloué à chaque frame, aucune mutation des définitions françaises.
- Code **4** pour balance 2 : payload 256 comme code 3, bit 128 pour refuge
  progressif ; suffixe obligatoire N0 sans caprice, S1..S3/C1..C3 sinon. Classique
  config 0 et N0. Lecture 1/2/3 = balance 1, encodage legacy strictement identique.
- Camp **9** seulement pour balance 2, champ balance:2 obligatoire ; mission
  cohérente, choix de copains conservés. Balance 1 garde les formats 4–8 et leurs
  octets ; lecture de tous les formats 1–8 préservée. Rejeter une fausse ancienne
  version contenant balance 2 ou une version future inconnue, sans écriture.
- Progression mission **2** dès qu’un départ/camp balance 2 est retenu ; lecture
  1 conservée et reconstruction sans perte. Comparaisons de départ incluent balance.
- Enveloppe familiale **5**, même forme complète que 4 (missions + albums), pour
  données contenant balance 2, y compris lastRuns/retryCamp/classicCamp. Lecture
  1–4 conservée ; données balance 2 mal étiquetées 1–4 rejetées. Les appels publics
  exportant un camp neuf doivent fournir missions et albums ; ne pas inventer
  des collections. Données legacy exportées selon les formats existants.
- Carnets restent format 1 et 36 cases, campagne/étoiles partagées ; noms ET
  annonces du fils restent exactement français. Import atomique et propriétaire
  du carnet sont conservés. Aucun nouveau prix appliqué à un ancien départ.
- Session/menus créent explicitement balance 2 pour les nouveaux départs ;
  reprise, code, réessai et autre configuration conservent la révision du départ.
  Tous les prix affichés suivent la partie, guide d’accueil = prix actuels.
  Un discret libellé « Règles d’origine » indique un départ historique.
